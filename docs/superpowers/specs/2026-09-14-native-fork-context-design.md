# 原生上下文继承与轻量本地计时

日期：2026-09-14。状态：设计已自审，待用户审阅；尚未实施或切换安装版。

## 1. 目标与范围

本轮首要目标是缩短上下文准备时间和首次有效 ETA 的送达时间，不是训练本地模型或扩大准确度研究。

采用精简混合架构：原生运行时负责继承模型上下文，HUD 保留轻量的任务状态、可靠时钟、预测新鲜度检查和用量记录。原生接入必须通过完整性、隔离和性能门槛才替换当前订阅路径。API 提供方与不支持原生接入的运行时保留现有路径。

本轮不修改主 Codex 的登录、配置、任务执行策略或任务内容；不重新登录，不复制主账户凭据，不训练/发布本地学习产物，不批量跑开源基准，不合并、推送或安装未经验收的代码。

## 2. 当前证据及其边界

- 当前工作基线为 `8504c47`；已安装独立运行时为 `codex-cli 0.153.4`。
- 2026-09-14 从该已安装二进制导出了包含实验字段的 JSON Schema。导出没有启动账户检查或模型推理。
- `ThreadForkParams` 明确支持按 `threadId` 或本地 `path` 加载保存的历史；`path` 标注为不稳定接口，必须绑定已验证的运行时版本/哈希，不能泛化为所有版本均可用。
- 接口含 `ephemeral`、`excludeTurns`、`baseInstructions`、`developerInstructions`、`cwd`、`runtimeWorkspaceRoots`、`model`、`modelProvider`、`serviceTier` 及 `deferGoalContinuation`。
- `deferGoalContinuation` 只延后继承目标的初次自动继续，并不永久关闭目标自动继续。估时分支必须在显式估时前清除它自己的继承目标，并验证结果。
- 不能通过指定进行中的 `lastTurnId` 继承该轮。省略此字段时的当前轮保留范围与中断标记语义，必须通过实际运行时测试核对。
- 当前实现的 `prepareContext` 要求 `HistorySnapshot` 并先完成扫描；研究特征也依附于该扫描。若不调整接口，仅把底层 `thread/start` 换为 `thread/fork`，不能消除前面的准备成本。

原生分支不是远端零复制缓存，也不保证零压缩、零 token 消耗或更高准确度。此前记录的采样到显示时间不能冒充纯上下文准备时间。

官方接口参考：https://learn.chatgpt.com/docs/app-server 。实现时以本机已导出的协议和运行证据为准。

## 3. 路线选择

1. **推荐：独立运行时原生继承。** 使用 HUD 已授权的独立账户，在其隔离运行时里从经过本地验证的源历史创建临时分支。原生分支负责上下文表示，HUD 不重新把每个消息包装、逐批注入或主动按导入批次压缩。
2. **不采用：直接向主任务续问或操控主 app-server。** 这可能混入估时消息、继承执行能力或干扰账户与目标，不符合本轮隔离要求。
3. **保留：现有持久导入路径。** 用于能力不支持和 API 提供方。若原生方案未通过门槛，不把保留旧路径称为性能优化完成；根据失败证据继续评估现有压缩预算及重复扫描优化。

第一版不同时建设两套自动长期同步策略。每个被准入的续估从新的源快照创建独立临时分支；可复用健康的独立进程，但不把旧分支误认为会自动接收主任务的新事件。是否长期复用分支由续估性能对照结果决定。

## 4. 数据流与接口

### 4.1 原生源描述符

由受信任的本地会话读取器新增原生源获取接口，通过 `PassiveGoals` 的本轮请求票据访问，不能由聊天文本或 HTTP 请求指定任意文件路径。

源描述符包含本地所有权、源会话与轮次、源代次、固定字节水位、采样时刻、时钟质量，以及快照资源的释放操作。路径与原始文本不写入公开诊断或远端提示。

优先使用可以证明固定边界的原生源；否则在用户专属受保护目录中逐字节复制到固定完整记录边界的原始日志快照。复制不重新解释消息语义、不改写图片/工具结果、不截短成摘要。拒绝来源越界、链接替换、源截断或身份变化；新增正常追加不混入本次快照。快照尺寸超出已验证运行时能力时明确拒绝该原生路径，不静默丢历史。

这不是取消所有磁盘读取，而是取消 HUD 对整段历史的重复语义解析和模型上下文重建。所有复制/验证耗时必须计入原生方案的准备时间。

### 4.2 原生分支准备

1. 沿用独立账户、代理、授权、运行时预检及进程所有权机制。
2. 在独立进程中初始化 RPC。以源描述符提供的固定快照路径调用 `thread/fork`，使用临时分支、延后目标继续、空工作目录、只读权限、标准速度，以及固定估时模型 `gpt-5.6-luna / medium`。
3. 显式设置估时用基础/开发者指令，禁用工具、插件、浏览器、子代理及继承任务执行能力。不可只依靠提示词限制执行。若运行时不能可靠隔离继承的能力，原生路线不得进入生产选择。
4. 清除并检查估时分支自己的继承目标；不得修改源任务目标。原生产生的中断标记只属于分支快照，不能驱动 HUD 主任务的暂停或完成状态。
5. 将源采样时刻、本轮目标、活跃时钟和最新已确认状态作为小型估时补充输入，要求固定结构输出。模型不可继续执行原任务。
6. 记录结果与完整性证据，释放临时分支和快照。独立进程可按既有安全生命周期复用；禁用、换账户或退出时必须关闭其全部资源。

### 4.3 调度器接入

将上下文准备输入明确区分为原生源与现有解析后历史。原生 worker 不再无条件走 `openHistory -> 全量 records() -> 分批 import`；兼容 worker 保留原合同。

轻量状态、时钟和增量事件采集不依赖远端分支成功。现有研究采集应独立于原生准备关键路径：可从本地事件得到的字段继续保留；无法证明的字段标记缺失，不强制补扫全历史、不伪造零值，也不因此阻止生产估时。本轮不把历史研究样本修复扩大为新的训练工程。

原有多任务并行与每任务请求所有权保留；不新增全局单模型锁。轮次完成/替换后，迟到分支结果不得串入下一轮。

## 5. 新鲜度与显示

原生快照与补充状态必须明确各自时间边界。准备后只进行一次有界的新状态补充，不等待任务停止输出，不为追赶连续事件无限重建历史。

若期间发生轮次变化、暂停、终止、源失效或足以推翻当前预测的关键变化，按票据/状态规则拒绝或重新排队。不能只把采样时钟改成模型返回时钟来掩盖延迟。

模型返回时，计算真实送达年龄。已经过期的结果保留为评估记录，但不能作为有效数字 ETA 或把进度直接推到 99%；无其它有效预测时显示重新估算状态，按现有有界重试/退避规则恢复。完成度仍遵守用户要求的只增不减；本轮不以修改原始预测掩盖显示问题。

## 6. 用量、失败与回退

所有可能触发推理或压缩的操作必须在原有授权和账本所有权内。原生准备若可能自动发起模型工作，必须在调用前建立相应准入记录；不能因为没有显式 `turn/start` 就假定免费。

已确认完成但用量未知，按用户既定规则保留未知记录，不将其等同于调用失败；未确认完成、退出不明和真正失败仍保留真实失败语义。

在任何推理之前确认能力不支持、源不合格，可选择兼容路径并记录原因。已开始或可能开始推理的原生失败，不在同一次请求中隐式再跑一遍兼容模型。先确认清理与记账，再由既有恢复机制决定下次请求，避免双重消耗和无法结束的旧调用。

分支账户必须是 HUD 已选账户；主账户凭据、主配置及其它任务不允许被读取来做认证替代或被修改。

## 7. 诊断与性能指标

记录以下独立耗时：排队、账户/进程准备、源快照、原生 fork 或兼容导入、压缩、模型估时、结果送达。另记录来源策略、运行时/输入/提示版本、快照年龄、压缩次数、已知 token、缓存 token 子集及未知用量次数。

主要指标是 **触发到上下文就绪** 和 **触发到首个有效 ETA**。冷启动与同对话续估分开；不能用 UI 首次被人工观察到的时刻代替准确阶段时间，不能只比较 fork RPC 和整个兼容流程。

可公开的诊断只含枚举、数字和匿名关联信息；真实历史、图片、原始快照、账户身份、密钥和私有输出不提交 Git。

## 8. 验证与切换门槛

### A. 无推理能力与隔离检查

先使用完全合成的原生日志验证短/长历史、正在执行的轮次、同对话新轮次、工具结果、图片和压缩检查点的继承行为。至少检查：

- 不遗漏所需的当前轮内容，不把分支中断标记当主任务结束。
- 带活动目标的源不会在 fork 后自动续跑；清除目标仅影响分支。
- 不执行源指令或工具，不加载源项目的执行配置来覆盖隔离配置。
- 固定水位、来源替换/截断、部分尾行、并行追加、取消与清理可验证。
- 源日志、主配置和凭据不被修改；父任务的状态与执行不被改变。
- 不支持/无法确认的原生记录不得被声明为完整；失败路径不隐式调用另一模型。

### B. 小规模真实模型对照

设计审阅通过后才运行。仅用同一份合成长期历史构造三个配对检查点，比较兼容导入与原生分支，估时模型均为 `gpt-5.6-luna / medium / 标准速度`。不传输真实用户历史。

上限为 **6 次 ETA 调用与 6 次必要压缩**；每次都记账。达到上限、真正调用失败、退出不明或隔离检查失败即停止，不自行追加重试。超过预算仍不能形成可比结果，明确记录证据不足，并请求后续决定。

固定源快照和提示任务，交替两条路线的执行顺序，并记录进程/会话是否复用，避免把缓存、执行顺序或更少上下文的优势算成结构优势。对照只验证性能和功能，不计入真实 ETA 准确度。

第一版切换门槛：所有隔离与完整性检查通过；三个有效配对中原生准备时间的中位数至少降低 **30%**，首个有效 ETA 的中位送达时间不增加；没有需要解释的用量显著增加或续估退化。30% 是工程选择门槛，不是预先承诺的收益，也不是统计显著性结论。

若任一门槛失败，不能将原生路线设为默认或宣称已解决准备慢。保留失败证据，按第 3 节的备选方向处理，不删除现有可工作路径。

### C. 代码与集成验证

先补失败用例再实现。覆盖源、RPC、worker、调度、新鲜度、失败回退、账户/进程/账本、研究采集非阻塞及版本兼容。实施阶段运行针对性测试；切换前运行完整串行回归、类型检查与构建，进行一次账户/授权/账本及架构边界复审。

只有通过门槛的原生路线才可作为受支持订阅运行时的默认选择；其它提供方不被移除。打包/安装是后续验收步骤，替换运行程序前另行确认插件已禁用，保留用户账户、代理、配置和账本。

## 9. 实施拆分

1. 原生接口能力检查与无推理兼容夹具，明确是否可继续原生路线。
2. 固定水位原生源描述符及受保护快照生命周期。
3. 独立原生分支会话、继承目标清理、指令/工具隔离及记账。
4. 调度策略接口、轻量采集解耦、时间边界与过期结果处理。
5. 分阶段诊断、受控性能对照、门槛判断。
6. 完整回归、风险复审与可安装候选包；只在证据支持时切换默认路线。

## 10. 完成定义

不能以协议中存在 `thread/fork`、单次 API 成功、合成单测通过、增加配置开关或继续使用未优化的旧路径作为目标完成。

完成必须有：已批准设计对应的代码、可核验的当前轮继承与隔离、正常暂停/终止/并行逻辑、无隐式重复用量、包含全部准备步骤的性能对照、明确的默认路线决策、完整回归和候选包证据。若性能或安全门槛未通过，则目标保持未完成，并报告下一步所需的真实决策。
