# 跨请求短时复用账户检查

日期：2026-09-15。状态：用户已明确确认“账户检查结果跨请求复用，最长 30 秒，每次保留授权与变更检查”的方向。本文件补齐并发、失效和验证规则，待书面设计审阅；尚未实现。

## 1. 目标与范围

减少同一 HUD 独立账户在多个任务或短间隔续估中重复完整账户读取的成本。不改变账户选择、远端接收方、模型、额度、代理、API 提供方、任务内容和安装版本。

这是原生继承＋轻量本地计时目标的公共配套优化，同样服务于兼容持久历史路径。不得用缓存命中的执行顺序优势证明原生继承更快，也不替代原生上下文、三个配对、准备时间降低至少 30%、首次有效 ETA 和续估门槛。

本设计修订 request-scoped-account-attestation 设计第 2、4 节对“检查结果”的跨请求共享限制，**不取消其一次性请求权限及精确所有权限制**。只缓存通过验证的检查结果，不共享模型调用权限、任务输入、账本准入、进程所有权或一次性请求句柄。

## 2. 证据、预期收益与选择

最新完整本地回归为 223 文件 / 2689 项通过；账户准备测量为 5335 ms，其中 account-read 阶段 4048 ms。该阶段包含元数据、进程和 RPC，不等于纯网络延迟。一次缓存本地校验仍需约 1 秒，原请求内 claim 和最终 guard 各约 1 秒；缓存不消除这些成本。

采用同一 identity runtime 内的**单条、内存、最长 30 秒**缓存。不增加跨进程存储、后台刷新或常驻账户 RPC 服务。后两者引入不同的存活、事件监听和崩溃恢复机制，本轮不做。仅增大哈希读取块预计收益有限，也不并入本轮改动。

缓存只对 30 秒内的多任务或短间隔续估有潜在收益；间隔更长时仍走完整检查。不承诺实现后达到原生性能门槛。

## 3. 缓存边界和时间

- 所有者是现有 createObserverIdentityRuntime 实例。不同实例、账户、受保护目录、提供方或运行时不共享缓存；不建立按用户输入路径或账户名称索引的全局 Map。
- 仅完成正常 prepareSession 全量检查、前后文件元数据一致、运行时与账户归属验证通过、子进程已确认退出时，可以发布缓存。inspect、登录、清理、API、显式压缩不建立新缓存。
- 内存记录包含不可变的账户/路由/资产绑定、原始 observedAt/expiresAt、原始单调时钟、身份文件元数据和构造受信任调用所需的内部状态。不得序列化到配置、日志、HTTP/MCP 或模型提示；不新增凭据内容读取。
- 寿命从**完整检查开始**计算，不是完成时刻。墙钟或单调时钟任一个经过 30,000 ms、原账户证据过期、非有限时钟或时钟回退，均不得命中。
- 命中、排队、后续验证、设置页检查、启动新模型进程均不续期。排队后及每个异步校验返回后重新核对有效期；开始命中不保证最终可用。
- 原始五分钟账户证据有效期不是缓存 TTL。不得生成“当前时间”的假 observedAt 来延长证据。

## 4. 请求路径

持久 worker 在正常上下文准备时，通过内部 prepareSession 参数显式允许缓存；默认及未传参数保持完整检查。该参数由受信任 worker 代码设置，不能从聊天文本、HTTP 参数或 ObserverInput 选择。

1. Desktop 保留现有 metadataTail 排队、授权状态和账户账本绑定检查。
2. Identity 若无有效缓存，执行现有完整检查。成功后生成一份新的一次性请求句柄，并保存可供后续请求验证的检查结果。
3. 若有候选缓存，先做新一轮本地校验：受保护目录归属、身份文件元数据、运行时/资产完整性、目录复核、取消及所有者状态。沿用现有检查强度，不减少哈希次数或权限助手检查。
4. 校验成功且原时间/绑定/失效代次仍有效，使用原证据返回调用准备结果，并生成**另一份独立一次性句柄**。不能返回上个任务使用过的句柄。
5. Worker 仍将句柄绑定至当前 prepared input 对象、任务、轮次、请求版本、源代次、worker、进程 PID/创建身份。claim 和模型发送前的本地 guard/同步检查保留。
6. 无法命中时至多进行一次现有完整准备；不重新排队循环碰运气。若完整准备也失败，走现有失败/恢复机制，不新增自动模型重试。

显式压缩、已准备请求句柄失效后的 observe 全量回退、首次登录检查、恢复检查使用“强制完整”路径。压缩仍单独授权和记账，不用 ETA 的一次性权限抵扣。

## 5. 并发和失效

不新增全局模型调用锁，已准入的不同任务可继续并行。现有短时元数据串行区保持；不把完整模型推理放入该区。Identity 内部若被并发直接调用仍按现有忙状态拒绝，不新增无界队列或等待者共享取消信号。

缓存和一次性句柄使用失效代次防止异步结果复活：完整检查开始时捕获代次，发布缓存/返回可复用句柄前核对；期间发生账户事件或撤销则拒绝发布。缓存验证函数必须可在缓存准备和原请求 guard 两种路径调用，不能等待当前调用自身持有的 pending 状态形成死锁。

| 事件 | 缓存 / 其它请求 | 当前请求 |
| --- | --- | --- |
| 同账户另一请求成功完整检查 | 可以替换缓存；不无条件吊销仍有效的旧请求句柄 | 各自保留原始期限及所有权 |
| 缓存自然过期 | 清除该缓存；旧句柄受其自身原期限约束 | 未发送前回退完整检查或按既有规则取消 |
| 身份文件、账户、路由、资产发生变化 | 清缓存并使旧代次句柄失效 | 不用旧绑定发送模型 |
| 任一所属估时进程报告 account/updated | 即刻使该 identity 的缓存和旧代次句柄失效 | 已提交调用保留真实终态/用量，禁止隐式再调用 |
| 授权撤销、登录/退出/换提供方、identity 禁用/关闭 | 失效并取消所属准备；关闭确认遵守原机制 | 沿用现有取消、清理和记账 |
| 本地校验失败、完整账户检查失败、运行时失效、退出不明 | 不缓存失败；失效，退出不明时禁止在旧结果上恢复 | 保留实际失败语义 |
| 单个任务在尚未进入身份检查前取消、正常完成或 release | 不因此撤销其它任务的有效账户检查结果 | 只作废该任务句柄及所属资源 |
| 身份检查已开始时被取消 | 本次检查不发布；涉及身份验证结果不确定则清缓存 | 无模型重试；不能把它视为成功命中 |

不以定时器或文件监视器作为唯一失效保证：每请求本地校验与发送前 guard 必须保留。无活跃估时进程时无法持续收到远端 account/updated；仅远端发生而本地未反映的变更，可能在最长 30 秒内未被新完整检查发现。这是短时缓存固有的新鲜度权衡，不声称与每请求远端检查完全等价；服务端拒绝或事件到达时按失败/失效处理。

## 6. 安全与用量不变量

- 一次性句柄仍只能消费一次；一个 prepared input 不能在另一任务、进程或轮次使用。
- 所有实际 ETA 和压缩分别保留授权、账户/账本绑定、准入、操作开始、真实终态、已知/未知用量和清理记录。
- 缓存命中不等于用户授权，不可通过缓存恢复已撤销同意；换账户不得借用旧账本。
- 发送前发现过期、失效或所有权变化时保留 cancelled-before-dispatch，不虚报成功、不制造模型用量。
- 调用已经发送后不因缓存失效启动替代模型调用。其结果是否可送达，继续由原轮次/状态/账本规则决定。
- 不修改已安装登录、主 Codex 凭据或配置；不传输真实历史，不清除旧失败或未知用量记录。

## 7. 验证和性能证据

先失败测试，再实现。覆盖：

1. 两个不同任务在原检查期限内只执行一次完整读取，各有独立句柄、各自实际模型准入；跨 worker 句柄使用仍被拒绝。
2. 原点 30 秒边界、完整检查自身过慢、排队过期、墙钟/单调时钟回退、最终发送前过期；命中不得滑动续期。
3. 身份元数据变化、账户/路由变更、account/updated、检查失败、授权撤销、关闭和退出不明；检查中失效不得发布新缓存。
4. 同账户另一请求的正常检查不错误吊销有效请求；单任务取消不误伤其它任务；共用队列无自等待死锁。
5. 缓存 miss 至多一次完整准备，无未经准入的模型调用；显式压缩、恢复及 observe 回退强制完整检查。
6. 非原生兼容路径同样使用该优化；API 与非持久路径不变。
7. 原始证据时间和隐私边界保持；诊断只记录数值/枚举，不包含账户标签、路径、凭据或可复用权限。

诊断明确区分 prepareSession 请求次数、完整账户读取次数、缓存候选/命中/失效原因、本地校验次数及耗时、排队时间和最终送达时间；先有无模型实测，再决定是否值得新模型实验。不能把“调用 prepareSession 一次”直接称为“一次完整账户读取”。

原生/历史对照须控制缓存状态：主要结构比较对每个测量显式走相同的强制完整检查；另用同源、同缓存起始状态的独立样本衡量公共缓存收益。若状态不匹配，该数据可保留但不计入原生结构提速门槛。不得让先执行的历史路径付完整检查成本、后执行的原生路径享受它的缓存，再据此宣布原生提速。

完成针对性测试后做一次新的 gpt-5.6-sol / medium 身份、授权、并发及账本边界复审，最多一次修复复审；完整回归在里程碑运行。过去请求内复用的复审不能替代本次跨请求边界复审。

## 8. 交付和完成定义

本次交付应包含实现、失败到通过的测试证据、实际命中/失效计数、冷/暖元数据耗时、复审和当前完整回归。无模型检查不会修改安装版；真实模型实验继续使用独立有界新审计，不重开 r9，不在失败后盲重试。

即使本缓存子项通过，原生上下文误认与完整性能门槛仍需解决。不会因此标记整个目标完成、自动合并、推送、打包或安装未验收的原生路线。

## 9. 自检

本设计只扩大经验证检查结果的复用范围；不扩大用户模型调用授权、不共享一次性权限、不延长时限、不降低已有本地校验。缓存收益与原生路线收益分开衡量。仅远端变更的最长陈旧窗口已明示，强制完整的压缩/恢复/回退路径已界定；所有异步发布受失效代次约束，无未定参数。
