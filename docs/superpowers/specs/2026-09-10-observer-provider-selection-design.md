# HUD 估时账户与 API 选择设计

日期：2026-09-10。状态：待用户审阅；尚未实现、安装或进行真实调用。

## 目标与范围

在已有设置页增加估时来源选择：一个 HUD 独立 ChatGPT 登录槽位，以及一个可编辑的 API 配置。任一时刻只有一个来源生效。用户可更换订阅账户，但本期不做多个已保存订阅账户列表、自动轮换、额度耗尽后自动换服务商。

主 Codex 登录与 HUD 登录独立；设置页明确显示 HUD 身份，不能仅因主程序换号就声称 HUD 已换号。不复制主程序凭据，也不要求用户在聊天中发送密码、验证码或 API key。

## 方案比较与选择

1. **推荐：统一观察者接口，分别实现订阅与 API 适配器。** 复用任务收集、输入整理、触发、倒计时与诊断，隔离认证和计费；本次工作量较大，但避免两套算法逐渐分叉。
2. 所有来源均通过 Codex CLI：能复用进程监督，但 API 的兼容性和故障仍依赖 CLI 运行时，不能充分简化链路。
3. 两套完整运行流程：接线快，但暂停、多对话、恢复和费用逻辑重复，不采用。

## 当前代码依据

- `observer-pilot.ts` 当前直接组合独立订阅身份、授权、账本和运行时。
- `observer-consent-store.ts` 的计费模式目前仅允许 subscription，需要版本化扩展，不能把旧授权直接解释成 API 授权。
- `observer-settings.ts` 已有可信窗口 IPC、修订号和一次性确认绑定，应扩展而非新增不受控 HTTP 配置接口。
- `openai-provider.ts` 是未连接的数字指标实验适配器，固定模型、价格、旧区间输出。不直接上线；仅复用有边界的响应读取、禁止重定向等经过测试的模式。

## 设置页行为

来源选择：ChatGPT 订阅 / API。

订阅区显示已核实的账户标签、身份检查时间、连接状态；提供更换账户、检查连接、一次估时试探。更换账户启动 HUD 独立登录流程，沿用代理设置；登录取消不自动切回并继续调用旧账户。登录成功后通过身份接口重新确认，不解析认证文件内容用于展示。

API 区提供名称、Base URL、协议、模型、推理强度（可选）、密码框密钥、调用预算。第一版支持 Responses 协议；仅兼容 Chat Completions 的服务商暂不支持，页面明确提示，不能笼统宣称所有兼容服务可用。模型由用户填写，不继承订阅模型 ID。订阅保留现有 Luna medium 配置。

保存设置只保存，不发模型请求。连接检查明确是否会联网，不能把本地格式检查标成认证成功；单次合成估时试探是独立按钮，明确会消耗用量。已有有效授权且来源未变时不重复弹窗。

## 运行与切换

统一接口提供身份/配置检查、估时、取消、关闭及脱敏诊断；估时返回目标关系、任务状态、剩余实际工作秒数、误差比例和可选用量。两条通道接收相同版本的任务快照与提示词，使用相同输出校验，模型不能执行工具或修改主任务。

切换顺序：关闭新请求入口 → 增加配置代号 → 取消或等待旧请求释放 → 保存并核实新配置 → 确认新来源授权 → 开放请求。无法确认旧资源释放时显示切换未完成，不启动新来源。迟到结果按配置代号丢弃，但费用仍归属原请求记录。

切换期间 HUD 保持显示，同目标有效估时保留并标注更新暂停；完成、暂停和用户等待语义不变。新目标清除旧估时。取消登录或新配置错误不导致静默回退或跨来源发送任务数据。

## 凭据、授权与代理

API 密钥由桌面主进程使用 Windows 用户绑定的加密保护保存，普通配置仅存密钥引用。无法安全保存时明确失败，不回退明文。渲染进程仅在用户输入提交时短暂持有密钥，提交后清空；读取设置只返回“已配置”，禁止返回原密钥。密钥不进入日志、诊断、账本、命令行、源码或 Git。

订阅沿用独立受保护登录目录和官方登录流程，本期不同时迁移凭据存储格式。切换只影响 HUD，不能退出主 Codex。新身份或新接收地址要求一次明确授权；未变化的绑定重启后复用授权。第三方 API 会把任务数据交给另一个服务商，页面须显示接收地址及此风险。

API 第一版仅接受 HTTPS 地址，拒绝 URL 用户名/密码、查询和片段；不跟随重定向，不关闭证书验证，不提供任意认证头编辑。用户明确配置的代理作用于对应通道，代理认证同样不进诊断。测试代理连接、TLS 错误、超时与取消，不假定浏览器联网就代表后台进程联网。

## 用量、预算和失败

请求记录绑定来源、配置代号及订阅身份指纹或 API 配置标识。旧账本只保留与迁移，不通过切换清空。订阅显示实测 token，不换算虚构美元；API 显示 token，只有价格配置有版本和来源时才显示估算费用，不能冒充服务商账单。

API 自动估时须配置每次输出上限与日调用上限；配置可靠价格后可加日金额上限及调用前预留。价格未知则明确金额未知，只执行次数/token 控制；本地预算不能保证服务商绝对不超额。未知用量记录保留，不能算作零费用。

认证失败提示重新登录或更新密钥；限流与暂时网络失败按退避恢复；不因一次网络错误永久停用，不无上限重试。未知用量不抹除，也不扩散成其他来源的虚假额度不足。账本完整性或资源所有权无法确认时仍停止相关调用并给出恢复入口。

## 验证与交付顺序

1. 来源配置、统一结果契约、旧订阅授权/账本兼容测试。
2. 订阅身份展示与更换流程；取消、换号失败和旧结果隔离测试。
3. API 适配器与安全存储；用模拟服务器覆盖合法输出、401/403/429、缺用量、超时、重定向、代理和畸形响应。
4. 设置 UI 集成；验证不泄露密钥、不自动调用或跨来源回退。
5. 全套回归、一次安全/认证/计费审查，再构建安装。安装仍先确认插件禁用，保留用户配置及回退包。
6. 用户完成需要的登录/配置后，各已配置通道最多一次明确授权的真实合成试探；真实调用成功不能作为 ETA 准确度证据。本次不做批量准确度测试。

## 文档依据与限制

- [OpenAI 认证文档](https://learn.chatgpt.com/docs/auth)：订阅与 API 是不同登录/计费方式，缓存登录须作为凭据保护。
- [API 认证参考](https://developers.openai.com/api/reference/overview)：Bearer 密钥是秘密，不能通过公开客户端接口或日志暴露。

上述隔离、接口、预算和 UI 是本项目设计决策，不是官方承诺。第三方服务兼容性、API 模型权限及代理可用性必须单独验证。

自检：本设计不包含私人账号、密钥或项目个人定位；明确了单槽位限制、协议范围、切换失败行为和预算边界。当前源目录不是 Git 仓库，因此此设计仅保存，未提交或推送；后续集成不得覆盖主仓库已有改动。
