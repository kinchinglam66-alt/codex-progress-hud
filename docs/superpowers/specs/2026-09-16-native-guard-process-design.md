# 原生资源校验进程复用设计

状态：2026-09-16 用户确认本文并授权按证据调整设计，无需逐次授权；直接实施后汇报。沿用本工作树“验证里程碑前不提交、不安装”的约束。

## 目标与证据

减少原生资源准备/清理中反复启动 PowerShell 的成本，不缓存或删减任何安全检查。零模型分项测量中，5条记录的回收总耗时5220.4415ms，11次存储检查2359.5533ms、15次进程退出检查2642.6717ms；这不是完整14.28秒释放路径的解释。整体原生 ETA 性能门槛仍未通过。

## 方案选择

采用有界、独占、只读校验进程：每次请求重新执行对应检查，复用的只是进程。保留一次性路径作为默认兼容实现。

不采用缓存“已退出/ACL正确”的结论；虽然可节约启动成本，但改变了逐项复核合同。不改用本机扩展模块：那会新增编译、签名和平台维护边界。

## 进程与操作边界

新增独立的固定脚本和传输组件，不扩展已验证的 home-check 帧协议，不赋予旧 helper 新权限。启动时绑定一个绝对独立 observer-auth 目录和一个资源所有者；不使用跨账户、跨目录的全局进程池。可信脚本的哈希、非链接路径和调用参数由宿主每次检查。

复审修订：启动使用宿主读入并核验哈希的脚本字节，通过固定 EncodedCommand 执行，不由 PowerShell 再打开脚本路径。拒绝多硬链接源文件，避免核验后替换路径造成未核验代码执行。每次请求仍重新核对磁盘资产。分配、claim 与 claimChild 的取消通过异步调用上下文传入嵌套校验；释放使用独立清理生命周期。诊断关闭逐个尝试全部所有者，保留全部失败名称，一个关闭失败不能跳过其他关闭操作。

只有两种请求：

- `verify_storage`：重新核对绑定目录及 hud-native/snapshots/custody 的所有者、保护ACL、允许SID、继承权限、目录及祖先非重解析点。与现有 native-storage verify 合同一致；不创建、不修复目录或ACL。
- `owner_exited`：携带经过范围验证的PID和十进制创建时间，重新打开并固定进程句柄，使用同一对象检查身份及退出状态，然后释放句柄。没有 Kill、任意命令或动态路径操作。PID重用按原身份已退出处理；不可核实结果绝不等于已退出。

现有目录创建仍使用一次性 prepare；文件头、文件身份、来源排除、删除ACK、文件消失和快照所有权检查仍留在现有 TypeScript 代码中。此 helper 不读取登录凭据、上下文或账本，不调用模型或网络，不执行删除。

## 帧与失败规则

输入为严格版本化JSON单行：`v,id,op`，仅 owner_exited 允许 `pid,creationIdentity`。ID安全整数、单调递增；PID为1..4294967295，创建时间1..20位十进制。拒绝缺失/额外字段、无效类型、重复字段、无效编码及未知操作。输入最多256字节，输出最多1024字节；输出严格匹配请求ID和操作，只有允许的结果枚举，不返回路径、任意错误文本或凭据。

单次请求6秒超时；空闲30秒退役；退出确认最多5秒。一个实例一次仅处理一个请求，同时请求明确报忙，不丢弃或覆盖原请求。取消、异常stderr、协议异常、过量输出及子进程异常立即停止本代次并等待真实关闭。关闭未确认时标记不可继续，禁止另起替代进程掩盖遗留所有权。旧代次输出不能满足新请求。失败不自动放宽到缓存结论；调用方保留原有清理记录。

进程报告检查失败或身份无法确认时，按原失败关闭逻辑处理；`live`是有效的“尚未退出”结果，不可用于清理。正常空闲退役且退出已确认后，下次可创建新进程，但所有检查从头执行。

## 接线和生命周期

`createNativeWorkerResources` 的可信可选配置接入实例级校验器；默认缺省仍用现有 createNativeStorage 和 isInvocationProcessIdentityExited。候选启用时，存储 verify 与只读退出探测通过同一个校验器逐次执行。不能通过对话文本或环境变量自行启用。

资源实例负责校验器退役：release 等待现有分配、复制、fork登记和清理全部结束后，finally 中关闭本次校验进程并验证退出。正常退役不使资源实例永久失效，后续合法分配可懒启动新代次；退出不明则实例永久拒绝新操作。清理失败时也要退役校验器，并保留未完成的持久所有权记录；不得提前清空记录或报告成功。不得强行结束外部进程。

取消回收工作的信号必须传递到正在进行的校验；不把发起任务已取消误当成“跳过必要清理”的理由。资源释放本身继续使用有界独立清理生命周期。

初期只由 native-observer-trial 的显式候选参数开启；比较两路线时不改变共同账户检查策略。现有 home-check、账户证明TTL、模型预算及安装版保持不变。

## 验证与准入

先TDD：真实Windows helper连续检查、调用间ACL/路径修改、活进程/退出/身份错配、输入协议及取消、错误代次输出、关闭失败。测试以真实目录和自有子进程为主，不以假验证器性能冒充真实结果。

再验证资源集成：正常和异常release均关闭helper；保持未清理记录；两独立目录/账户不串用；并行请求不串答；安全失败不得变成清理成功；单次扫描与来源保护回归继续通过。

性能对比至少3组交替顺序，纳入冷启动和最终退出，使用真实存储与退出检查。分别报告纯守卫、完整本地清理和端到端ETA，保留未测部分说明。通过局部优化不意味着整体通过；仍要求原85KiB/1MiB完整性、准备改善30%、有效送达不退化、无不明token增长及同轮退化、总生命周期不增加。

完成一次安全/所有权复审及至多一次修复复审、完整回归、类型检查和构建后，才进入既有授权的合成端到端试验。实现由当前任务直接完成，不派实施子代理。不因本设计自动合并、推送或安装。
