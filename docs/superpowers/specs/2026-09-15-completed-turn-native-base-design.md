# 已完成轮次原生基底＋当前轮完整补齐

日期：2026-09-15。状态：用户已确认本书面规格，进入实施计划与分步验证；尚未替换安装版。实施和实测结果在对应计划及报告中记录，不以规格确认代替验收。

## 1. 目标与修订范围

ETA 只预测当前主任务轮次从采样点到该轮结束所需的剩余实际工作时间；用户等待、暂停不计入。估时内容边界与主任务轮次边界相同，不预测需要多轮交互的整体目标。

采用用户提出的分工：能原生继承的历史由原生分支继承；插件仅补齐原生继承边界之后、截至本次触发采样点的上下文。例如第 7 轮执行中触发时，原生继承第 1—6 轮，插件补齐第 7 轮开始到触发点的完整可读记录与运行事实。

本规格修订 `2026-09-15-native-owner-reuse-design.md` 中“每次请求一份完整原始快照”的规则。继续保留每次 ETA 独立分支，不采用 `../reports/2026-09-15-account-cost-followup.md` 中曾提出、但未实施的“长期复用已有 ETA 回答的分支”方案。其余账户、授权、账本、进程回收和验收约束不变。

原生 fork 是继承已存储的原生历史，不承诺远端模型记忆直接复用、免上传、免输入 token 或免压缩。初次建立基底仍可能需要本地快照和原生读取；优化重点是消除同轮每次重做整串历史准备，而非宣称完全不读取本地内容。

## 2. 已核对的实现与能力

- 当前 `observer-native-fork.ts` 调用 `thread/fork`，但没有传 `lastTurnId`。
- 当前 `local-session-reader.ts` 的 `nativeSnapshot` 复制到已观察完整记录水位；`native-source-snapshot.ts` 验证路径、源身份、内容边界和自有目标后复制固定前缀。
- 当前 `context-owner.ts` 绑定源对话及活动轮次，准备后重查绑定；这些检查必须保留。
- 固定运行时 0.153.4 的 `ThreadForkParams` 明确支持 `lastTurnId`：包含指定轮，排除后续轮，指定轮不能正在运行。因此第 7 轮正在运行时仍可请求继承到第 6 轮，不必等待主对话空闲。
- `path` 导入属于不稳定接口，必须继续绑定已验证运行时与格式；独立 HUD 账户不能仅凭主任务 threadId 被假定拥有主任务存储访问权。
- `excludeTurns` 仅避免响应携带整串 turns，不是缩减模型继承上下文的开关。

官方语义参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。实现以本机固定版本 schema 和无模型兼容性验证为准。

## 3. 流程与分支职责

### 3.1 建立本轮继承边界

主任务来源读取器识别真实轮次开始和终态事件，记录源对话、源代次、轮次 ID、完整记录偏移及原生检查点身份。不得根据“没有输出”、聊天标题、助手声称完成或 fork 生成的中断标记推导边界。

第 N 轮第一次需要 ETA 时，取得相互绑定的两部分：

1. **历史基底**：截至上一已结束轮次的原生源历史；此前失败或中断但已结束的轮次同样是历史，不因不是成功状态而丢弃。终态是否可作为该运行时 fork 截止点须由兼容性测试确认。
2. **本轮补充**：第 N 轮开始至本次固定触发水位的全部可读源记录，以及相关会话级上下文变化。

初次基底通过已有受保护快照导入独立运行时。调用 `thread/fork` 显式指定可信的上一终态轮 ID，并持久登记新分支所有权。不得将当前运行中的轮 ID 作为 `lastTurnId`，也不得省略边界后假定运行时自动选对。

基底不执行 ETA、探测或工具，不接收当前轮补充，也不接收任何估时回答；它只提供不可变的主任务历史。新基底的目标仍须清除并验证为空，源主任务完全不改写。

### 3.2 每次 ETA

每次 ETA 从本轮不可变基底创建一个全新、自有的估时分支。在独立运行时内优先使用已登记基底的 threadId 进行 fork，不再为同代次每次请求复制整个主任务历史。

每个新估时分支追加该次**完整本轮前缀**，而不是仅追加自上次估时以来的差量：它们分别从同一个历史基底出发。插件可以增量读取、验证并缓存本轮源记录，以避免重复磁盘读取，但发送给新分支的内容必须覆盖本轮开始到本次水位。

例如本轮第一次估时在 t1，第二次在 t2：两次分别使用“历史基底＋本轮开始至 t1”和“历史基底＋本轮开始至 t2”。第二个分支不能继承第一个分支的 ETA 回答。本地倒计时仍可使用先前数值；它不是主任务事实，不能混入源记录。

模型只获得估时职责及来源明确的历史资料。主任务历史中的指令、工具调用与结果作为待分析记录，不赋予估时分支执行主任务、访问工作区或继续旧目标的能力。沿用进程级工具禁用、RPC 服务端请求拒绝、只读沙箱和独立工作目录。

### 3.3 首轮与不兼容来源

首轮没有已结束历史时，创建干净的估时会话，完整补齐首轮上下文；不得虚构上一轮 ID，或用运行中首轮作原生截止点。

若来源缺失可核实的截止轮、压缩检查点无法表达该边界、原生格式不兼容或历史完整性无法证明，不能将不完整结果标记为原生完整继承。仅在既有完整历史路线自身能证明完整且已获同一提供方授权时使用该路线，并记录回退原因；否则保持未知并诊断，不发送猜测拼接的上下文，不静默裁剪。回退也不得额外重试一次已失败的模型调用。

## 4. 完整性、去重与新鲜度

### 4.1 基底身份

基底绑定源对话、稳定源代次、上一终态轮 ID、该轮终态记录边界、原生检查点身份、固定前缀摘要、自有文件身份、运行时哈希、账户与配置代次，以及 worker owner UUID。不能将每次增加的快照 revision 当成历史改写，也不能把仅有相同文件路径或 mtime 当成内容一致证明。

源读取器维护经过核验的轮次索引与完整记录水位。正常追加只更新当前轮增量；历史覆盖写入、截断、文件替换、检查点改写或无法证明追加一致性时撤销旧基底资格，按既有清理规则重建或回退。首次追赶来源可能仍需完整扫描；此成本必须计入冷启动。

### 4.2 本轮补充

补充保留用户输入、助手 commentary/final、工具调用及截至水位已出现的结果、可读图片/附件信息、必要会话级配置变化和本地运行事实；沿用已有内容与附件验证，不扩大为任意文件读取。没有可信轮次归属的记录不能凭时间相近硬归入当前轮。

去重使用经过解析验证的源记录身份、轮次和顺序，不使用文本相同作为依据。重复出现的同一句用户要求、工具输出或不同轮复用的工具标识不得误删。基底已含记录不能再次出现在补充中，本轮记录不能误算进基底。

准备开始固定触发水位：只包含已观察的完整记录，不读取半行或水位之后的结果。尚未返回的工具保留“调用中”及可核实已运行时间，不捏造结果。模型请求的所有本轮记录来自同一固定视图，不在序列化时继续追尾。

内容采样时间和临近发送时的运行时钟分别标记。准备中出现新源记录可按现有调度策略请求后续续估，不能偷偷改变已准入请求的固定输入。准备期间轮次已结束、暂停、等待或被新轮替换时，撤销本次发送资格；迟到 ETA 不得写回新轮。

## 5. 生命周期、并发和用量

### 后续用户确认的修订：跨轮运行时复用

用户在 series03 结果及换轮成本说明后确认：同一对话、同一账户与授权绑定且健康时可跨轮保留运行时；每轮仍新建历史基底、每次 ETA 仍新建子分支。以下修订取代本节原有“等待/完成/新轮必然退出进程”的部分，其他规则不变。

- 将进程身份与轮次身份分离。只有已经结算、持有未过期保留许可的空闲进程可以跨正常轮次结束间隔保留；不凭新轮事件延长原有截止时间。没有许可、来源失联、暂停、失败、撤权或不健康状态继续退出。
- 主轮结束立即撤销旧请求发布与模型发送资格；保留进程不代表主任务仍运行。正常完成/等待下一次用户输入可保留空闲进程，不能在等待中调用模型。
- 新轮开始后，先重新验证账户、来源身份、源代次和进程健康，再创建新基底。旧基底仅保留清理托管记录，不参与新轮 fork；旧 ETA 回答、请求凭证、监听器和用量基线不复用。
- 旧资源仅在已确认进程退出后清理，全部基底/快照计入 64 MiB；最多 3 次请求按整个进程累计，不按轮重置。原有空闲 60—1860 秒范围不扩大。达到上限仍正常退出重建。
- 此授权不改变内容/性能验收门槛，不允许安装未达标候选，也不允许压缩不可变基底或跨轮继承旧 ETA 会话。

继续按对话隔离 worker、账户证明、请求票据、分支监听器和用量基线。不增加全局模型并发限制。同对话模型操作和代次清理继续遵守现有串行所有权，不以共享基底绕过授权与准入。

基底在同一活动源轮次、同一健康进程代次内复用。现有每代次最多 3 个估时请求、64 MiB 已知资源回收阈值、空闲 60—1860 秒规则保持不变；另登记最多 1 个只读基底分支及其快照，全部计入资源总量，不把基底误计为模型调用。达到阈值先清理旧代次，再重建同轮基底；所以不承诺一轮不论多长都只复制一次。

切换到下一主轮次时，建立新的原生基底，包含刚结束的真实主轮次；不从旧估时分支拼接主历史。暂停、等待、完成、禁用、退出、账户或授权变化继续立即撤销复用资格，按已确认退出后再清理的规则回收，用户返回后重新准备。

基底和请求分支分别持久登记创建意图、tag、ID、文件及进程身份。取消、fork 返回丢失、进程退出不明、删除失败保留可恢复证据；不得删除主任务、未知所有者或仍被运行进程使用的资源。只有整个代次关闭并确认后，才回收其共享基底。

每次真实 ETA、必要压缩仍独立准入与记账；原生准备若意外启动模型操作也必须捕获、记账并判该次预检失败。已确认压缩完成但 token 不可核实，按现有规则保留未知用量并继续；不能用 0 替代未知。新架构不改变生产调用频率、预算、隐私设置或登录数据。

## 6. 组件变更边界

- `local-session-reader.ts`：可信已结束轮次边界、稳定源代次和当前轮固定水位读取；不得新增全历史常驻副本。
- `native-source-request.ts` / `native-source-snapshot.ts`：表达基底边界与本轮补充的配对身份；初次受保护快照及其复用合同。
- `context-owner.ts` / `conversation-source.ts`：一次获取配对视图，准备后核对来源与当前轮有效性。
- `observer-native-fork.ts`：明确原始基底 fork 与自有基底 fork 两种可信来源，传递并验证截止轮，不接受聊天或外部请求指定源路径。
- `observer-persistent-worker.ts` / `native-worker-resources.ts`：代次拥有共享不可变基底，每次请求拥有全新分支和完整本轮补充；拆出聚焦的基底管理单元，避免继续扩大 worker 的混合职责。
- 调度、时钟与诊断接线：记录采样时点、基底冷/暖、补充数量、回退原因和分阶段耗时；复用现有结束/暂停规则，不用估时模型覆盖权威运行终态。

账户证明及其哈希/ACL 检查不属于本次优化切片；若后续另做公共优化，两条比较路线必须同等受益。

## 7. 验证与性能门槛

先做无模型验证，覆盖：首轮、第 7 轮中途、同轮两次触发、自然切轮、已失败/中断历史、部分 JSON 行、重复文本/工具 ID、工具未结束、图片、终态与准备竞争、源追加/改写/截断、压缩跨越轮次、路径替换、取消、迟到 fork 回答、关闭失败、资源阈值以及两对话并行。断言当前轮不在基底中、补充从轮首开始、不含水位之后结果、无旧 ETA 回答污染、源文件不变和所有权正确回收。

固定运行时预检验证：运行中主轮存在时指定上一终态 `lastTurnId` 可 fork；自有基底再次 fork 保持历史一致；原生继承后本轮补充保留角色与工具配对；没有任何推理或工具自动启动。预检不通过先定位，不用真实历史掩盖兼容性失败。

真实模型试验使用既有持续授权，gpt-5.6-luna / medium / 标准速度，先用合成上下文。不为每批重复询问额度授权，也不把授权解释为新一轮真实私有历史传输许可。预先固定批次、样本与停止条件，失败记录保留，修复后用新编号，不自动盲重试。

正式配对至少覆盖冷启动、实际普通续估间隔后的同轮暖态、新轮冷态 3 个检查点，交替执行顺序。包含小上下文和更长合成历史分层，记录大小、原生基底创建成本、当前轮补充准备、账户检查、排队、fork、模型、清理、首次有效结果、已知/缓存/未知用量。不能把提前建立基底的成本藏在统计窗口外。

延续原门槛：完整性和隔离全部通过；3 个有效配对的完整准备中位数至少改善 30%，首次有效 ETA 中位送达时间不增加，无未解释的 token 增长或续估退化。所有配对与预定样本均报告，不能挑选有利子集通过。端到端收益与纯上下文准备收益分别列出；账户检查耗时不因分支方案自动消失。

到稳定里程碑执行完整回归、类型检查、构建与一次架构/账户/账本风险复审，最多一次修复复审。内容继承或性能试验不是 ETA 准确度证据；准确度评测另需真实完成边界和工作时间标签。

## 8. 本轮交付与非目标

### 2026-09-16 已确认的传输优化修订

用户确认完整本轮补充可随 ETA 请求提交，容量或压缩不适合时保留完整原路径。候选 worker 显式开启 inlineCurrentTurnSupplement，默认关闭；仅 prepareNativeTurnContext 使用，不改变历史路线。

先暂存可完整提交的有界文本补充，不调用 inject_items，不推进已导入 cursor。新子分支的 turn/start.input 先携带同序 observedRecord 引用，再携带当前观察请求；原生完成轮基底不接收补充。暂存记录数、水位和字节量与已导入字段分开，请求确认不冒充历史注入确认，也不允许再次使用已提交补充的 ETA 子分支。

图片、长文本、数量或容量超限时，先完整冲刷暂存前缀，再走既有序列化/注入/压缩路径，不丢记录。模型准入前以最终观察值和输出 schema 构造、拥有并核对完整请求；合并请求超限先回退导入，原路径仍超限则零 ETA 准入返回。发送前的来源、账户和取消检查，发送后的用量保全和晚到结果检查不变。诊断读回发生在注入已确认或请求已接受之后，不能将尚未发送的暂存数据称为落盘证据。

仍按整体准备、有效结果到达和生命周期成本验收，不因阶段搬移而放宽门槛。单次兼容性成功不是性能或估时准确度证明。

本书面规格明确继承与补充的边界，随后按 writing-plans 流程产生实现计划、分步 TDD 和受控验证。此次不清除用户资料、不改变已安装插件、不提交其他既有改动、不推送个人材料，不创建新的侧边栏任务。

不加入本地模型训练、自动修改主任务、无限寿命估时分支或所有账户共享上下文。候选切换仍须满足原验收条件；目前并没有已经提速的实现或性能结论。
