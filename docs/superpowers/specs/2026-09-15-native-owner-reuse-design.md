# 原生估时：有界进程复用与压缩信息验证

日期：2026-09-15。状态：用户已确认本详细设计，进入实施；最长空闲 31 分钟及暂停/等待/完成提前回收等边界保持不变。

本文件补充 2026-09-14-native-fork-context-design.md，不替代其完整性、隔离、用量、新鲜度和性能门槛。已完成的账户缓存保持独立，不把它的收益当作原生继承通过验收。

## 1. 证据与目标

- r10 前两组原生准备分别约 9.56/9.52 秒，历史路线约 8.09/6.64 秒。原生每次重新启动进程，退出后清理另需约 3.8 秒。
- 普通续估间隔为 300/600/900/1800 秒，事件请求保留 60 秒冷却。此前空闲 30 秒回收的建议已撤回；不能改变调用频率以制造复用收益。
- r10 第三组历史路线未取回工具编号。实物检查点经过本地读取与发送前序列化后内容一致；远端压缩保留或检索仍未证明。第三组原生调用未执行，不能称为原生单独失败。
- 目标仍是可靠继承当前轮上下文、缩短完整准备和首次有效 ETA 时间，不是缓存命中率、协议调用成功或少发几个 token。

## 2. 方案选择

采用：每个对话独享可回收的独立进程，每个估时请求独享全新原生分支和固定水位快照；已结束分支暂留至进程退出后统一清理。

不采用长期复用同一个估时分支：它不会自动继承主任务新事件，且旧估时答案会污染后续上下文。不采用删除活跃进程所拥有的文件，也不把“thread/delete 返回成功”替代进程退出证明。

不采用仅将旧清理任务移到后台作为完整优化：这不能消除下一次进程重启，也可能把未清理资源与新请求混在一起。

## 3. 生命周期与保留规则

### 3.1 独立进程代次

- 每个会话的进程代次绑定：本地对话键、源轮次、账户/路由/资产指纹、运行时哈希、PID 和创建身份、随机 owner UUID。
- 不跨对话共享进程，不新增全局模型并发锁。源轮次切换即淘汰旧代次；后续轮次仍从当前源上下文重新继承。
- 进程仅初始化一次 RPC；同轮续估创建新的 session 对象和 thread/fork，重新清除并验证该分支目标，重新绑定请求票据。不得复用旧 session 的 threadId、累计用量基线、订阅监听器或 prepared-input 授权。
- 每个模型操作仍独立准入和记账。保留进程不代表保留一次性调用授权；账户检查、30 秒账户证明缓存及请求最终校验按原规则执行。

### 3.2 空闲截止时间

- “空闲”从请求终态及必要账本写入完成、确认无进行中操作后开始；准备中和推理中不是空闲。
- 调度器只传内部可信的保留许可，包含源轮次/代次、确认运行状态、最近请求时钟及下次普通续估资格。聊天文本、HTTP 参数不得指定保留时间。
- 最初截止时间为下次普通续估预计时刻加 60 秒宽限，并夹在空闲开始后 60 秒与 1860 秒之间。计算使用同一单调时钟；壁钟仅用于展示/持久诊断。
- 轮次仍运行时，普通状态轮询、无效事件、设置页访问不能延长截止时间。只有另一次已确认结束的真实估时操作可产生新的空闲期。
- 31 分钟不是整个进程的总寿命；连续真实续估可产生多个空闲期，但每代次最多 3 个请求，达到下述阈值即回收，不无限累积历史分支。
- 无可靠调度许可、时钟异常或源身份无法确认时不保留。休眠恢复后先重新检查截止时间、状态和身份，再允许复用；不靠可能延迟的定时器单独判断。
- 暂停、等待用户、完成、轮次替换、账户失效、禁用或全局退出立即撤销复用许可。已在执行的操作按现有取消/终态流程收尾；不能在退出不明时删除资源。
- 这里的 31 分钟是正常运行条件下触发回收的空闲上限，不承诺电脑关机/进程崩溃后文件会按时消失。恢复启动依现有所有权和进程存活检查清理。

### 3.3 有界资源

- 初始每个进程代次最多 3 个已登记请求分支（含当前请求），对应最多 3 份原始快照。每份源快照继续使用现有已验证尺寸上限，不因复用提高 8 MiB 原生试验安全上限。
- 初始每代次已知快照、所属分支日志和清单总量达到 64 MiB 时不再复用。每次准入前和操作终态后检查已登记资源；不能遍历真实主任务历史来测量。
- 64 MiB 是回收/准入阈值，不是对远端运行时写盘量的操作系统硬配额。运行时单次超量、大小不可核实或文件身份改变时，撤销复用、保留诊断并关闭所有者；不宣称已强制限制其写盘。
- 达到数量或字节阈值，先确认旧所有者退出并完成清理，才允许为同一会话建立下一代次。不可通过连续新代次累积退出不明的旧进程。
- 第三个请求正常结束后或终态检查已达到字节阈值时立即回收，不再等待下一个请求或空闲定时器。
- 资源上限只影响进程复用，不减少任务数、改变估时触发频率或授权预算。其它对话保持独立并行。

## 4. 资源所有权与回收

将当前“一个 worker 一份 lease”拆为“一个进程代次，多份请求 lease”。每份 lease 保存自己的原始快照、源身份、分支 tag、分支 ID、文件身份与 child PID/创建身份；分支 RPC 前先持久登记 intent。

请求正常结束只标记该请求 lease 不再使用，不调用其 snapshot.close 或 afterProcessClosed。新请求分配新的 lease，不覆盖旧引用。准备失败产生的半成品也必须登记并在代次回收时处理。

调度占用释放、模型终态、用量完整性和进程退出是四件不同的事。正常终态可结算已知用量并允许同对话下次准入，但所有者仍存活时保留真实的待清理/未退出证据；不得伪写 processExit，不重复结算用量，也不把已完成而暂未清理的调用误判为仍在推理。恢复对活跃代次与退出不明代次保持原有区别。

代次回收严格串行：

1. 同步撤销本代次复用与新准入，增加代次栅栏，取消空闲定时器。
2. 等待必要的终态/账本写入，关闭对应独立进程，核验 PID 与创建身份退出。
3. 使用已有无推理清理运行时，按本代次持久 tag 删除所有自有分支，再删除所有自有快照及清单。
4. 清理确认后释放内存引用，才可进入下一代次。

关闭/删除失败保留全部可恢复证据，不把失败清单当作无效缓存删除。源文件、其它对话、主账户和未知所有者资源不可触碰。恢复仍兼容旧清单；新清单字段若需要版本升级，旧版本必须有明确读取与恢复测试。

定时器与新请求竞争时，仅一条串行生命周期路径胜出：请求先取得当前代次则旧定时器失效；定时器先撤销许可则请求不得复用，并等待清理。不允许双进程代次同时接受同会话操作。

## 5. 接口职责

- observer-scheduler：从可信任务状态生成/撤销保留许可；每次状态更新和最终 release 都处理。不能为保持进程而提前调用模型。
- desktop/observer-runtime：按对话转发内部生命周期许可；保留 worker 与关闭 worker 明确区分；禁用/换提供方覆盖全部活跃与空闲代次。
- observer-persistent-worker：进程代次与请求 session 分离；隔离 threadId、监听器、请求证明、账本和迟到结果；健康同代次才复用进程。
- native-worker-resources：管理多个独立 lease，按已确认退出代次批量回收；不取消现有路径、ACL、文件身份检查。
- native-snapshot-custody/native-fork-custody：保留“先持久登记、后使用”和“确认退出、后删除”合同；恢复不依赖内存计时器。
- 诊断：增加复用/重启/回收原因、进程代次匿名标识、资源数量/已知字节、空闲截止剩余值。只输出枚举、计数和耗时，不输出历史、路径、账户指纹或密钥。

## 6. 压缩问题的独立定位

不把进程复用视作压缩问题的修复。先做一个独立合成试验，最多 3 次 ETA 与 1 次必要压缩，模型保持 gpt-5.6-luna / medium / 标准速度：

1. 在单独的原始历史分支中验证首条用户标识、配对工具结果、最新进度标识和图片，不把其回答写进压缩用分支。
2. 另一份相同源分支先压缩，再在原分支验证同一组事实。
3. 提取该次压缩的原生检查点，在新独立会话导入后验证同一组事实。只导入压缩检查点与预先固定的源尾部，不导入步骤 2 的探测问题或答案。

保留压缩项身份、源/检查点指纹和时间边界。检查点必须来自同一次已确认压缩；若后续自动压缩改变它，停止该试验。不得用不同次压缩输出冒充同一输入，也不得通过提示预填预期编号/颜色。

结果解释：

- 原始分支已失败：先处理原生上下文检索，不能继续归因于压缩。
- 原始通过、压缩后原分支失败：证据指向压缩保留或压缩后检索；仍不能解密并断言具体摘要内容。
- 压缩后原分支通过、同检查点导入失败：优先查检查点恢复/提示和账户兼容边界。
- 全部通过：只是一份合成样本通过，不承诺压缩无损或真实 ETA 准确。

失败不自动重试。未知压缩用量仍保留。定位后才提出有证据支持的修复；不预先加入手工关键事实缓存、裁剪、补写答案或另一套主历史同步系统。未经门槛验证仍不安装原生路线。

## 7. 验证与验收

### 生命周期（先无模型）

用受控单调时钟验证 5/10/15/30 分钟调度、1860 秒上限、无效轮询不续期、休眠/壁钟跳变、阈值回收及新请求/定时器竞争。不靠真实 sleep 等待半小时。

覆盖：同轮同账户 PID 复用但新 threadId；旧分支不接收新请求；暂停/等待/完成/新轮/禁用/换账户回收；中途取消、复制未完成、fork 回复丢失、关闭未确认、PID 重用、替换文件、旧清单恢复；多对话相互独立；无账本复用和迟到结果串轮。

先运行本机固定运行时的无推理多分支生命周期试验，验证正常关闭与恢复真实资源均清空，源不变，未启动任何推理。工具隔离和授权校验不得因性能优化被删掉。

### 内容与性能

压缩定位试验与正式对照分开编号和记账，不重开 r10；诊断记录不得混入正式中位数。

正式对照仍需 3 个不同源检查点、交替顺序、同源/同提示/同模型/标准速度，每轮最多 6 ETA 和 6 必要压缩。两路线账户缓存采用同等政策；结构对照继续同时 bypass，另行报告真实生产缓存配置的端到端表现。

除密集协议试验，还必须覆盖实际调度间隔的冷/暖生命周期；单元仿真只能证明保留逻辑，不冒充真实分钟间隔性能。不得缩短生产调用频率，或通过忽略清理/账户/队列/快照耗时声称提速。

原门槛不变：完整性与隔离全部通过；3 个有效配对的完整准备中位数至少改善 30%，首次有效 ETA 中位送达时间不增加，无未解释的 token 增长或续估退化。报告末次回收耗时和峰值资源，不能只报告模型回答耗时。

到稳定里程碑运行全套回归、类型检查、构建及一次账户/账本/生命周期风险复审，最多一次修复复审。仅对新切片复审，不重复已完成账户缓存复审。全部通过后才准备候选包；安装前确认插件禁用并保留用户资料。

## 8. 完成边界

这一修订不减少总目标，不以缓存优化代替原生完成。进程复用有效、压缩定位完成、内容与性能门槛通过、回归/复审/候选包证据齐备后，才能提出默认路线切换。任何门槛未过，记录具体差距，不隐藏失败或重复开试验赌通过。

最初设计提交未修改运行代码、建立付费审计或替换安装版。用户确认后的实施及验收证据单独记录于 `../reports/2026-09-15-native-owner-reuse.md`；本设计的通过条件不因实施进度而降低。
